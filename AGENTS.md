# NkMail contributor instructions

- Build an actual Qt Quick mail client using canonical Kos.Ui from the pinned `third_party/nextkdeAppDemo` Git submodule and mailio for IMAP, SMTP and MIME. Initialize with `git submodule update --init --recursive`. Do not replace the mail backend with curl or duplicate the component library.
- Keep the UI gitlink fixed to a tested source release; never automatically follow `main`, latest releases or `git submodule update --remote`. Make shared component changes in the canonical upstream repository, not as uncommitted edits in this submodule. `NKMAIL_UI_SOURCE_DIR` is an explicit local-development override; use a fresh/default-source build for release acceptance and record the tag and full SHA when upgrading.
- Before an integration PR, stage the chosen UI gitlink and `third_party/kos-ui.lock.json` (release tag + full SHA), then run `python3 scripts/check_ui_dependency.py`. It requires a clean initialized submodule and a matching published upstream Release; do not skip failed/network checks or automatically publish upstream. Use `python3 -m unittest discover -s tests/dependency -v` for guard regressions. Cover newly used/dynamically loaded QML with loading/behavior tests.
- Main changes go through a PR and the required Actions `release-gate` check, including administrators. Do not direct-push main, bypass checks, force-push, weaken protection or substitute local override builds for the clean CI build. Single-maintainer PRs need no second-person approval. A release upgrade updates the gitlink, lock, README and NOTICE together after upstream publication.
- KMusic is an architectural/visual reference; calendar in quickshell is a dialog/popover reference only. Do not modify or launch the reference projects. Preserve their working trees.
- Default: compilation, GUI execution and automated validation run in the designated VM. On 2026-11-02 the user explicitly authorized host compilation and launching NkMail for this systray feature task. This exception covers NkMail and its pinned Kos.Ui dependency, not reference projects; automated regression tests remain VM-only.
- Current scope: multiple accounts, application-password authentication, browsing/search, sanitized reading, attachments, durable drafts, sending and explicit flag/move/delete commands. Validate writes only against synthetic loopback fixtures. No real mailbox mutation is authorized. Never fall back from targeted deletion to mailbox-wide EXPUNGE.
- Never disable TLS verification or downgrade to plaintext. Apply and document the small required mailio TLS/PEEK fixes. Credentials use QtKeychain without insecure fallback.
- The user later supplied a specific enterprise account in the conversation for local read-only provider verification. Do not reproduce those credentials here or in files, tool logs, public output or subagent prompts. Do not inspect existing mail clients or extract their credentials. Only after TLS/PEEK tests pass may a narrowly scoped login/header/content test use that supplied account; do not try alternate passwords automatically. No real SMTP submission or mailbox mutation. Public testing artifacts always use synthetic `.invalid` data and loopback servers that cannot relay outside.
- Repository `https://github.com/NextKde/NkMail.git` is PUBLIC. The user explicitly authorized periodic commits/pushes and screenshots at useful milestones (roughly 2–3 effective iterations). Use synthetic data in screenshots and progress reports. Never upload credentials, personal mail, machine configuration, raw logs or build products. Never force-push.
- Local temporary outputs belong in `tmp/`; build outputs in `build/`. Curated synthetic screenshots and concise reports belong in `docs/progress/`.
- Use GPLv3-compatible licensing and preserve third-party notices. Keep component-library sources canonical; record source revisions and do not copy KMusic's dirty vendor tree.
- Keep GOAL.md current with verified milestones, failures, blockers and next actions. This is a recovery record, not a native Codex goal or a promise of execution after this session exits.
- The user authorized installing the missing Arch `boost` development package, without a system-wide upgrade. Ask before other privileged system changes or unrelated installations.
- Real external mail sending and destructive mailbox operations are not authorized. SMTP server acceptance is not delivery. Preserve drafts and never automatically retry ambiguous sends.

- Feature modules own their state: AccountSession, MailboxSync, MailboxCommands, DraftService, SendService and RemoteImageLoader. Keep MailController as the QML adapter; do not reintroduce direct protocol/HTTP work or separate single/batch implementations there. Inject MailTransport for service regressions.
- Database opening must never perform interrupted-send recovery. Call explicit recovery once at startup after the profile lock, before background work. View components expose inputs/signals and must load independently of Main.qml IDs.

- Sidebar toggle must use the shared KosSidebarToggle rounded sidebar glyph, consistent with Weather/Calendar; do not replace it with VectorIcon panelLeft. The sidebar header has no compose button; compose remains in the main toolbar.

- No permanent bottom status bar, including an empty footer or Demo caption. Content extends to the window bottom; show actionable errors/lifecycle notices only on demand. Theme switching lives in More.

- Interactive previews must respect session-wide SingleInstance ownership. Do not accumulate demo windows/tray icons during UI iterations; replace the owned preview when updating the binary. Screenshot exports are isolated and create no tray.

- Keep Simplified Chinese and English catalogs complete for all new interface/application diagnostics. Use qsTr/tr or explicit translation contexts, preserve placeholders, and run nkmail_i18n/nkmail_translations in the VM. Do not translate user mail or arbitrary provider text.
